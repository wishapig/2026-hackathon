## ABI、访问与别名

公开签名为：

```cpp
void cholesky(double *A, double *L, int b, int lda);
void trsm(double *A, double *L, double *X, int b, int lda);
void madd(double *A, double *B, double *C, int b, int lda);
```

块元素使用 `base[row * lda + col]`，不是连续 `b*b` 存储。推荐源码每次传入 `lda=n`，块起点来自完整行主序矩阵中的偏移。索引、尺寸和 ABI 的 int 转换必须检查范围，不能把本地源码中的 int 乘法当作无限范围保证。

| 算子 | 本地实现的调用边界语义 | 推荐源码中的别名 |
| --- | --- | --- |
| cholesky | 读取 A 的下三角，生成 L 的下三角并将块内上三角写零；内部读取的 L 值由本次调用先前步骤生成 | A 与 L 为同一对角块 |
| trsm | 读取完整 A 块和 L 的下三角，完整写 X；先把 A 复制到本地 scratch，内部读取的 X 值已由本次调用生成 | A 与 X 为同一块；L 是另一个对角块 |
| madd | 读取完整 A、B 和原 C，执行 C -= A*Bᵀ，完整写 C | 对角更新时 A 与 B 相同；C 与两输入块不重叠 |

基础访问契约可保守使用完整块：cholesky 为 R(A)、W(L)，trsm 为 R(A)、R(L)、W(X)，madd 为 R(A)、R(B)、R(C)、W(C)。实际相同地址先归一化为同一资源，再构造 RAW/WAR/WAW 并去重。调用内部的先写后读不能误当成未定义的外部输入，也不产生任务自环。精确三角访问可作为后续优化，但必须包含 cholesky 的上三角写零和 madd 的完整块读写。

上述仅证明推荐调用的已观察别名组合，不能推广为任意部分重叠均安全。尤其不能把 madd 的 C 与输入重叠视为合法通用用法。非已证明别名需明确契约或拒绝该并行模式。本地实现没有创建线程或共享可变全局状态，trsm 的 scratch 为每次调用私有；对正式二进制版本仍需核对语义指纹、内部线程和重入契约。

## 完整算法与任务数量

推荐入口先复制 A 的全部元素到 L，再按以下结构调用官方接口：

1. 对当前对角块执行 cholesky，输入输出原地相同。
2. 对其下方各块执行 trsm，读取当前对角结果并原地写该列块。
3. 对剩余下三角各块执行 madd，使用本轮两列块更新目标块，包含对角目标。
4. 全部分块调用完成后，将完整结果矩阵的严格上三角清零。

复制与清零都是必须保留的算法语义，也计入计算时间。基础设计把它们作为明确前置/后置阶段；若未来与其他工作重叠，须用区域访问证明合法，不能静默忽略。块内 cholesky 清零不替代最后的全局上三角清零。

由实际循环得到 q=n/b 时：cholesky 共 q 次，trsm 共 q(q-1)/2 次，madd 共 q(q-1)(q+1)/6 次，总内核调用数 V_kernel=q(q+1)(q+2)/6。公开最大 q=48 对应 48、1,128、18,424 次，总计 19,600；q=6 时总计 56。该计数不包括复制/清零的语义任务，编译器必须独立从源码推导，不能将公式写死在通用 runtime。

## I/O 与校验边界

新头文件按 `uint32_t count`，随后每条 `uint32_t n`、`uint32_t b`、`n*n` 个 double 读写。它直接 reinterpret_cast 到字节并使用 sizeof，没有字节序转换或浮点格式规范化，因此只能据此确认宿主表示格式，不能宣称任意异构平台互通。它检查打开和指定字节数读写失败，但未检查 n/b 合法性、尺寸预算、有限值、正对角线或尾随数据；输出写入也未核对向量长度等于 n*n。

因此项目仍须保留受检容量、元数据、有限值、正对角线和残差检查。此前 public20 残差函数的 NaN 误通过没有被这个读取器的有限值检查兜底，因为读取器没有该检查；本轮仅做源码核对，未编译运行完整文件级漏洞复现或公开 20 条流程。

## 赛事方后续澄清及计时落实

用户转述的最新规则是：矩阵文件 I/O 与结果校验不计时间，除此以外 Metadata 加载、解依赖、执行、写结果均计时间。项目据此将结果缓冲分配/初始化、A→L 复制、内存中结果写入及上三角清零计入，不能把 Metadata 文件读取误归为免计时的矩阵文件 I/O。文件写出与结果内存写入分别记录。

示例 main 在 `result.l.assign` 之后才启动计时，只计 block_cholesky，并把各 case 时间相加写入 COMPILER2026_TIMING_FILE；它展示的是推荐 baseline 行为，不能作为将我们额外准备、加载 Metadata 或结果初始化移出计时的授权。项目计时口径以赛事方后续澄清为准；最终评分聚合、并列排名与计时接口细节仍需正式规则确认。

多个输入必须严格依次处理，前一矩阵的计算与依赖活动结束后才启动下一矩阵；可复用不可变 Metadata 和线程池，但首次成本及每次重置均按规则计量，不能通过跨输入计算/准备流水隐藏开销。Metadata 的具体内容由方案决定，仍按必要算法产物完整统计；本地展开图属于运行内存与准备成本，不等于可以把必需依赖藏入不计费外置文件。

正式性能测试聚焦分块 Cholesky，专家审查方案对其他算法的适用性。三个接口是该评测算法的强制计算接口，不是通用工具链永久封闭的算子集合；新增算子通过契约与 ABI 适配扩展，依赖推导和调度器保持通用。问题 1、2 的原始问句及问题 7 所指群回复未在当前资料中给出，不补造其内容。
