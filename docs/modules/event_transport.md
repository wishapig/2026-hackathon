> **实现对照（2026-10-30）**：当前 `owner` 后端在 `src/runtime.cpp` 使用每所有者加锁收件箱与预留的每边链接 `event_next`，按 CSR 边 ID 交接通知；不是环形 MPSC、生产者聚合缓存或部分接受协议。`atomic` 后端直接递减。下文有界队列背压、SPSC 和聚合方案是后续候选。 当前实现见 [实现说明](../implementation.md)。

以下保留模块职责与候选接口；函数名不等同于当前公共 API，实际接口见 `include/dag/core.hpp`。

## 单一职责

在线程之间交接 SourceTask、EdgeArrival、RetireTask 和失败控制事件。不解析算法依赖，不扣减计数，不决定任务优先级。源任务可由驱动直接递交本地分片；远程事件使用同一交接语义。

这是消息后端的控制通道，不是每条依赖的强制路径。基础原子后端直接应用 EdgeArrival，连续状态不需远程 RetireTask；就绪远程注入由 ReadyScheduler 管理。逻辑通知无需堆对象，直接调用和消息发送必须二选一，避免重复递减。

## 接口与所有权

try_send(owner, batch) → accepted_prefix_count；poll(owner, work_budget) → events。发送者拥有未接受的后缀，接收队列拥有接受的前缀。返回值不能含糊为“可能已发送”。同一生产者对某个缓冲批次只在交接成功后释放或复用存储。

消息后端初始实现选择每所有者一个有界 MPSC 收件箱，加每生产者有限的聚合缓冲。每个槽位定义明确的发布、消费和回收协议，必要时使用序列号防止环形复用错误。控制事件与就绪任务队列分开，避免调度策略改变依赖交接正确性。

EdgeArrival 至少带 target_key，调试模式带 source_key；RetireTask 带源任务身份。事件可跨类型乱序到达，业务模块不得依赖未声明的全局 FIFO。Release 发布、acquire 接收形成内核写的可见性链；批量缓存不能在内核完成前提前发布。

## 背压与公平性

队列满立即返回未接受部分。驱动交还控制、处理本地收件箱、刷新其他可发送批次，并保留后继枚举游标。所有 worker 都有待发送数据时仍必须能消费收件箱；不在发送操作中自旋等待另一 worker 完成内核。

聚合缓冲设置容量和刷新期限，空闲前、执行结束前及达到期限时强制刷新；低流量关键路径不能为了凑批量无限等待。预算涵盖主队列、待发批次和必要的有界溢出存储。紧急失败标志使用独立可观测状态，不能依赖一个已经塞满的普通收件箱。

## 性能取舍

先测每所有者 MPSC，若争用显著再对照线程对之间的 SPSC 通道；后者有 O(P²) 通道和轮询成本，不因无锁就自动更快。生产者/消费者频繁写入字段隔离缓存行，优先批量发布，测量通知延迟和吞吐，不能只优化平均每事件纳秒数。
