> **实现对照（2026-10-30）**：当前格式已固定为 `DAGMETA1`：8 字节 magic、uint64LE JSON 长度、uint64LE FNV-1a64，再接确定性紧凑 UTF-8 JSON。实际保存参数化程序及访问表达式；没有 varint、ZigZag、共享表达式 DAG 或符号后继段。FNV 仅检查意外损坏，不认证来源。实现见 `compiler/compile.py`、`src/metadata.cpp`，格式细节见 [编译器说明](../../compiler/README.md)。下文分段压缩编码为候选方案。 当前实现见 [实现说明](../implementation.md)。

以下保留模块职责与候选接口；函数名不等同于当前公共 API，实际接口见 `include/dag/core.hpp`。

## 单一职责

将 SymbolicGraph 编码为可独立解析的版本化产物，并将该产物还原为 DecodedMetadata。接口为 encode_graph(graph) → Artifact 与 decode_metadata(bytes, limits) → DecodedMetadata。它不生成或补救依赖。

## 编码设计

采用带 magic、schema_version、段长度和摘要的二进制容器，段包括参数、算子、表达式、任务族、关系和入口。文件内整数选择固定的小端布局；这是新 Metadata 的设计选择，不推断官方矩阵文件的字节序。

表达式使用共享 DAG 与常量池。无符号字段使用有长度上限的 varint，有符号常量使用明确定义的 ZigZag 编码；重复符号与类型用表索引。公共关系片段可引用共享定义，禁止用压缩逃避实际依赖数据的大小统计。

表达式节点具备类型与溢出语义；关系指令仅允许有界循环、条件和输出，不支持任意函数指针或任意机器码。程序合法性由编译器证明并在解码/绑定中校验结构、引用和参数限制。扩展指令需增加兼容能力标记，未知必需能力明确拒绝。

ExecutionHints 段可保存从同一源码自动生成的 IndexProgram、OrderProgram、循环结构和成本/能力标记；缺失某项时不得凭猜测启用对应模式。连续 ID 不默认是拓扑序。提示若影响正确执行就是必需产物，计入 Metadata；软优先级不改变依赖。缓存的具体任务状态/CSR 在实际参数绑定后生成，属于运行时内存与准备成本，不把预存公开实例图伪装成通用提示。

## 性能与存储所有权

磁盘布局服务于字节数，解码后的结构服务于缓存与解释成本。一次解码为对齐数组、紧凑操作码和索引，热点不执行逐事件 varint 解码。DecodedMetadata 在所有使用它的 BoundExecution 销毁前保持不可变且有效。

报告总字节、各段字节、解码时间和解码内存。调试符号可以单独存储，但若运行依赖它就必须计入总量。未来专门化产物、必要字典和外置契约遵守同一原则。

## 15 分编码项与运行成本

Metadata 是动态依赖的表达和存储，赛事未限定必须包含某一种图结构。本设计仍选择参数域、任务族和关系程序，可附加由源码自动导出的索引/原顺序能力；不把本地格式选择写成赛事强制规范。压缩只改变编码时应保持逻辑图与执行语义相同。

比较原始结构编码、表达式共享和紧凑编码等候选时，同时记录必要文件总字节、分段大小、Metadata 文件读取、解码/绑定与 T_score。更小但明显拖慢总时间的产物不自动胜出；85/15 是排名分值而非可相加的时间/字节系数。可选压缩字典、契约、专门化代码或辅助文件若运行必需则列入清单，不把算法信息搬进可执行文件后宣称 Metadata 为零。正式计费细则未明确时采用完整清单审计口径。
