# ExecutionDriver：执行生命周期与进度

> **非规范文档**：项目唯一需求与验收依据见 [REQUIREMENTS.md](../../REQUIREMENTS.md)。本页仅说明实现、使用方式、设计候选或历史验证；其中的约束性表述不能新增、覆盖或缩小规范要求。

> **实现对照（2026-10-30）**：当前生命周期由 `src/main.cpp` 与 `src/runtime.cpp::Executor` 共同实现，含线程池复用、失败排空和严格多 case 顺序执行。首任务为 `__copy` 时单独提取为前阶段，末任务为 `__zero_upper` 时独立提取为后阶段；两项不要求同时出现，内部同类任务保留图语义。前置复制延至图与执行器存储准备完成后，确保资源回退发生在任何数值操作之前。Metadata、分配初始化、建图建池、复制清零及必要清理均计时。没有运行中表示切换或高扇出续传游标协议。 当前实现见 [实现说明](../implementation.md)。

以下保留模块职责与候选接口；函数名不等同于当前公共 API，实际接口见 `include/dag/core.hpp`。

## 单一职责

连接模块以推进一次 BoundExecution，从建立资源到完成排空或安全失败。接口为 execute(bound_execution, runtime_options) → ExecutionResult。它不重新计算依赖规则，不实现队列内部算法，也不接管分片计数。

## 工作循环与职责分配

驱动持有线程池、每线程临时空间、源枚举续传状态、已完成任务的后继游标、待交接批次与执行生命周期计数。按绑定器资源计划设置线程 affinity，并在允许节点上组织首次触页；初始化语义来自算法契约，成本按计算路径统计。

计数模式执行前按 ExecutionPlan 创建状态与队列，调用 DependencyTracker 完成全部连续计数初始化，启动同步后才发布源任务与调用内核。V 个状态、pending 记录、队列、完成游标和线程空间的预算在此兑现，分配与触页计入准备成本；连续数组排空后整体回收，不逐任务复用槽位。

每次循环按有限预算处理本地控制事件、待发批次、完成游标、待发布就绪任务和源任务，再获取并调用一个或有限个就绪任务。每个类别都有周期性服务机会，不能只在计算队列空时处理控制事件。唯一源枚举器可以由一个指定 worker 驱动；它必须可暂停，不能充当所有任务的中央派发器。

内核完成后，驱动通过 GraphEvaluator 枚举后继。原子后端直接调用 accept_edge；消息后端将 EdgeArrival 交给目标分片。所有后继均成功应用或交接后才登记传播完成；逻辑 retire 由接口处理，连续模式不发远程退役事件。高扇出分批推进，保存已接受前缀，不重复应用。

批量领取仍保留每个细任务的唯一租约。每次调用结束即推进其依赖，不在批末统一释放；控制循环按调用数量和预计时间预算交还控制。预算不足容纳更多完成游标时，先推进现有游标和可释放容量的工作，不无限累积私有已领取任务。

## 完成与排空协议

绑定时得到总任务数 V。每个执行租约仅能登记一次传播完成，包括零后继任务。正常完成候选条件为源枚举结束且传播完成数等于 V；随后进入排空屏障，确保所有 worker 停止产生新事件、消费剩余控制事件、回收状态并清空局部待发缓冲，再返回成功。

传播计数是单调计数，使用每 worker 发布计数或分批归并减轻共享热点；最终判断读取经过同步发布的值。不能在仍有任意生产者时仅靠队列 empty 的瞬时快照返回。排空屏障必须在所有传播完成后进入，提前进入会阻止别人继续解依赖。

每线程的未发布计数在有限期限、空闲前和停放前刷新，避免最后一小批永远达不到发布阈值。接收事件在依赖模块确认接受前保留在本地待处理缓冲；读取收件箱不等于该依赖已经生效。

V = 0 时无需任务调用，但仍需完成源枚举和资源收束。多矩阵可复用线程池和不可变 Metadata，必须使用新的 execution_id、绑定和任务状态；一次返回前旧执行引用全部退出。赛事要求多输入依次处理：禁止跨矩阵执行、窃取或合并任务，本设计也不将下一矩阵准备与当前计算重叠。

具备 OrderProgram 时另提供 original_order 模式：通过原顺序游标逐次调用全部语义任务，不创建计数和消息，不进入上述源计数协议；游标真正耗尽、在途调用归零且资源收束才成功。用于串行参考、小工作量候选和显式状态放不下时的低内存路径。首次内核调用前选定模式，不能在并行执行半途直接重跑原顺序。

## 计分时间与源码前后阶段

仅矩阵文件 I/O 与独立结果校验排除。驱动所需配置、Metadata 加载、建池、绑定、状态初始化、计算、排空和结果整理全部计时；共用准备/收束只计一次，不藏在逐 case 计时之外。使用 [需求规范](../../REQUIREMENTS.md) 的 T_common、T_case、T_finalize 与 T_score，T_execute 仅作诊断。

demo 的复制 A→L 和最终上三角清零必须纳入明确的语义前后阶段，或生成等价依赖任务。若作为阶段，复制完成后才启动相应计算，全部需要的数据计算结束后再清零；不重复生成同一操作。内存写结果计时，矩阵写文件不计时。不能照搬 demo main 中把输出分配放在计时外的做法来漏算必要准备。

## 背压、错误与公平性

交接失败时保留候选和偏移，下一轮先做能释放容量的消费工作。待完成游标、ReadyPending 和发送缓存也有预算，不能把无界堆积从队列转移到驱动。可用额度不足时暂停获取更多内核任务，继续推进控制事件；若无法在预算内保持进度，发布 ResourceExhausted 并安全退出。

暂停获取只针对无法保留其完成状态的工作，不得在队列已满、pending 无法发布时同时禁止消费就绪队列。原子连续模式预留唯一 pending 记录和受限游标空间；消息模式待发满时仍须消费收件箱。动态观测仅调整软展开、批量与可丢弃缓存，不能删除在用状态或将额度减到低于已发放量；必要时安全失败。严格有界窗口和执行中表示切换尚未作为已支持能力。

失败路径原子记录首个错误、停止新增派发并唤醒所有 worker，等待已进入内核的调用返回，再清理事件和状态。失败路径允许丢弃该执行尚未执行的任务，不把失败结果输出为成功矩阵。挂起检测使用“无在途调用、无源或游标进度、无可处理事件”的同步诊断；单纯超时不能证明图死锁。
