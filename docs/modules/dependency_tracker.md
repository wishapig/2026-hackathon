# DependencyTracker：依赖就绪状态

> **非规范文档**：项目唯一需求与验收依据见 [REQUIREMENTS.md](../../REQUIREMENTS.md)。本页仅说明实现、使用方式、设计候选或历史验证；其中的约束性表述不能新增、覆盖或缩小规范要求。

> **实现对照（2026-10-30）**：当前由 `src/runtime.cpp` 的 `Executor` 实现连续计数，支持 `atomic` 的 acquire-release 递减和 `owner` 的单所有者递减；入度来自去重 CSR。执行排空后重置状态。没有稀疏状态、链进度或独立的 ReadyPending API；预留每任务队列链接避免就绪发布时动态分配。 当前实现见 [实现说明](../implementation.md)。

以下保留模块职责与候选接口；函数名不等同于当前公共 API，实际接口见 `include/dag/core.hpp`。

## 单一职责

维护尚未完成的不同前驱数量，并生成唯一就绪事件。不执行内核、不选择 CPU、不枚举后继。接口为 initialize(graph, plan)、accept_source(key)、accept_edge(target, optional_source)、peek_ready(worker, budget)、confirm_ready(key)、retire(key)。具体策略见 [运行时策略](../runtime_strategy.md)。

## 第一实现：连续状态与直接原子递减

当 ExecutionPlan 选择 dense_atomic 时，使用 DenseTaskId 索引连续存储。计数热字段与调试/参数冷字段分离，SoA 或紧凑 AoS 通过基准选择；owner 不必逐任务保存，可由映射计算。分配全部计数及每任务唯一待发布记录所需容量，不在每条边上分配对象、不在热路径查哈希。

准备阶段通过 GraphEvaluator 枚举有效任务并初始化去重前驱计数。并行初始化也必须在启动同步点前全部完成；零前驱任务随后由唯一源入口激活。只读初始计数如缓存，仍须逐执行重置可变计数，禁止完成通知与初始化交错覆盖。

完成者直接调用线程安全的 accept_edge，不等待目标所有者收件箱。每条合法边仅递减一次，原值为 1 的唯一递减者获得 ReadyPending 发布权。起始零前驱任务仅通过 accept_source 获得发布权。重复边在调试模式以 source_key 检测；生产模式依赖经验证的去重和恰好一次交接，检测到非法零值递减/下溢立即失败，不能继续运行损坏状态。

ReadyPending 由归零者所属 worker 的发布账目持有；其他递减者不再发布。队列拒收时保留同一条记录，重试不能再次扣减。pending 可用每任务预留链接和每 worker 链表组织，不为满队列额外无界分配，也不靠反复扫描全部 V 找就绪。先安排可消费工作，避免“先清空全部 pending 才允许执行”造成停滞。

## 发布与生命周期

逻辑生命周期为 Waiting、ReadyPending、ReadyPublished、Running、KernelDone、Retired；无需把所有观测阶段编码成一个多写者共享字段。依赖模块负责发布权，调度器负责唯一执行租约，驱动负责完成与传播。

peek_ready 只借出调用者拥有的候选。try_enqueue 的成功接收点允许执行者立即取得任务；随后 confirm_ready 只清理发布账目，不将已 Running/Done 的任务状态写回 ReadyPublished。失败接收则维持原发布权。调试状态也须使用不会倒退的同步协议，不能引入新的数据竞争。

基础连续数组在一次执行最终排空前地址稳定；retire 只表示逻辑退役，不复用槽位，不为它发送远程消息。最终确认计数调用、发布者、队列租约及游标引用均退出后整体释放或重置。这样避免单任务回收与“最后递减者尚未返回”等竞态，多矩阵仍使用新的 execution_id。

## 内存序与消息对照

原子基线每次成功递减使用 acquire-release 的 RMW，沿同一计数的原子修改顺序汇聚所有前驱写；唯一归零者再 release 发布就绪任务，执行者 acquire 获取。初始化由启动同步发布。后续如使用 release 递减加最后 acquire fence，必须另行证明，不能凭压力测试删减同步。检查目标 AArch64 原子宽度和生成代码；不默认某扩展或编译选项必然可用。

对照后端 dense_owner 使用相同逻辑图、连续布局和调度器，但按稳定映射将计数交给单写所有者，远程 EdgeArrival 通过 EventTransport 发送。消息 release/acquire 与后续就绪发布构成可见性链。窃取仅移动执行权，不能转移状态所有权。所有者执行长内核可能推迟归零；是否以较少缓存竞争换取更短总时间必须实测。

原子后端的发布目标默认为完成者可安全写入的就绪队列，远程亲和通过调度器受控注入；不把它强制重新绕回目标所有者。两后端都必须区分“消息已交接”与“计数已应用”，保留未接受后缀。

## 按需与压缩候选

稀疏状态可用分片 slab/表；首次发现必须安装一个初始化完成的唯一对象，不能让多个前驱覆盖彼此计数。首次初始化、查找同步和回收均需计费。状态最坏 O(V)，池耗尽只返回未应用的 retry 或失败；不能承诺按需等于有界前沿。稀疏原子对象的单任务回收需要独立引用安全协议，否则保留到排空。

链进度是可选表示，不替代原始细任务及跨链依赖。启用前须证明连续完成语义、下一步的全部外部依赖、唯一领取、精确唤醒与进度寿命；GraphEvaluator 计算门槛，DependencyTracker 持有可变进度。没有完整证明和收益时继续使用基础计数器。
