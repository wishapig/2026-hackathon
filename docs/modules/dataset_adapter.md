> **实现对照（2026-10-30）**：当前 `src/main.cpp` 实现严格两位置参数 CLI、逐 case 文件协议校验、有限输入检查、临时输出后 rename；`tools/check_result.cpp` 独立验证有限值、正对角线和残差各中间结果。矩阵文件 I/O 单独排除，缓冲分配初始化与结果整理计时。 当前实现见 [实现说明](../implementation.md)。

以下保留模块职责与候选接口；函数名不等同于当前公共 API，实际接口见 `include/dag/core.hpp`。

## 单一职责

将指定文件协议转换为矩阵缓冲区，并将执行结果写回文件。接口为 read_batch(input, format_profile) → MatrixBatch 与 write_batch(output, results, format_profile)。它不改变 n/b，不计算 Cholesky，不控制任务调度。

## 协议配置

当前 public20 配置依据压缩包内 `compiler2026_public20/docs/io_format.md`：uint32_t case_count，随后每条记录为 uint32_t n、uint32_t b、n × n 个 double；输出同样包含数量、n、b 和完整矩阵。程序命令接受输入文件与输出文件两个位置参数。记录顺序与输入一致，逐条保持 n、b；格式中没有 seed、q、行填充或块填充字段。

demo 已提供 include/matrix_case_io.hpp，其记录布局与 public20 说明一致，直接以宿主 uint32_t/double 的对象字节读写，没有字节序转换或浮点格式规范化。应使用该头文件做互操作基准，不能宣称跨字节序兼容，也不通过文件长度猜测是否有 b。详细证据见 [demo 审查](../demo_review.md)。

输出上三角在 public20 配置下写零，下三角来自计算结果。demo 算法先复制 A→L，原地调用官方算子，最后清零完整结果的严格上三角。适配器可以提供受检缓冲/清零操作，但执行顺序由算法语义和驱动管理，不重复清零、不遗漏阶段；复制、结果初始化和内存写入都计入计算时间，不能因操作在适配模块内就归为免计时 I/O。

## 内存与计时

赛事方明确只排除矩阵文件 I/O 和结果校验；Metadata 文件加载不属于该豁免，结果缓冲准备、矩阵复制和内存中结果写入仍计时。矩阵文件读写单独记录，不能把后处理混入免计时段。demo main 把 result.l.assign 放在计时外，仅是 baseline 实现细节，项目采用后续澄清的完整口径。

缓冲区由 MatrixBatch 持有，执行完成或安全失败前不得释放。可逐矩阵读取处理以控制内存，但所有 case 必须依次执行，不能跨矩阵计算或把下一 case 的准备与当前计算并行隐藏成本；复用线程池或不可变 Metadata 不等于允许多输入并发。

解析前检查 case_count、尺寸乘积、总字节及可用预算；矩阵格式只承载赛题字段，资源策略与调度参数通过独立运行配置进入。资源不足或截断输入报告失败，避免部分结果被当作完整输出。

public20 配置先验证 n > 0、0 < b <= n 与 n % b == 0，再做经过溢出检查的容量计算，不要求 b 或 q 为二次幂。按 uint32_t 为 4 字节、double 为 8 字节的公开布局，文件长度为 4 + Σ(8 + 8*n²)；20 条规格合计每个输入/输出文件 120,455,332 字节。逐矩阵模式仍须检查累计字节和记录数；额外尾随数据在本地严格配置下拒绝；demo 读取器没有尾随数据检查。它也没有尺寸预算、n/b 合法性、有限值及输出向量长度验证，项目不能照搬这些缺口。
