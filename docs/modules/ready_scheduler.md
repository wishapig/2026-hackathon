> **实现对照（2026-10-30）**：当前 `src/runtime.cpp` 使用每工作线程加锁双端队列，预分配每任务 next/prev；本地 LIFO，定期获取最旧任务，空闲线程逐任务窃取。`DAG_BATCH` 是控制循环最多执行调用数，默认 1；没有按成本自适应批量、关键路径优先级或链压缩。 当前实现见 [实现说明](../implementation.md)。

以下保留模块职责与候选接口；函数名不等同于当前公共 API，实际接口见 `include/dag/core.hpp`。

## 单一职责

将已就绪的任务分配给一个执行者。输入只能是 DependencyTracker 生成的 ReadyTask；输出 TaskLease。接口为 try_enqueue(ready)、try_acquire(worker)、release_lease(result)；release_lease 仅归还调度资源，结果与后继处理由驱动负责。

## 初始策略

每工作线程一个本地双端队列，本地优先获取，空闲时从其他线程有界批量窃取。来自远端的入队通过受控注入接口完成，不能把单生产者队列直接当成多生产者队列。队列可采用已验证的算法；首次实现允许使用局部锁以建立可信对照，不凭“无锁”标签选择生产策略。

采用可配置但算法无关的窃取顺序与批量，窃取只移动执行权，不移动依赖分片。ReadyTask 中可有由通用访问契约生成的亲和提示，优先级只能来自 Metadata 或可测量的通用策略，不硬编码某类 Cholesky 任务优先。

本地 LIFO 有利于局部性，但可能推迟旧任务；通过定期服务旧任务、远端注入和有限连续执行避免饥饿。每执行有限任务批次后将控制权交给驱动，保证通知、源枚举与完成游标继续推进。

队列在固定执行上下文内优先存紧凑 DenseTaskId。原子后端归零者可向自己的本地队列发布，避免强制等待目标状态所有者；远程亲和走受控注入。批量 acquire 每个 ID 仍有独立租约；不需要为减少队列操作先把 DAG 合并成大节点。

不静态均分链数或任务数。基础策略先用小批工作窃取，随后按算子类型/形状的抽样耗时估计每批工作量，同时限制数量和预计时间，避免 worker 私藏长队列。工作短且全局就绪量充足时增加批量；尾部、窃取失败或其他 worker 空闲时减少批量，独立范围可拆分，严格链不能并行拆成两段。反馈统计按线程低频聚合，不在每个任务上更新全局热点。

可选 try_acquire_batch 返回有上限的唯一租约集合；运行中不能因某成员尚未就绪而阻塞整批，因为该接口只接受已经就绪的节点。范围描述符只有在编译证明全部成员可执行、且领取不重叠时才替代节点 ID；待考察范围属于生成器，不混入 ReadyTask 队列。直接续执行必须取得同样的唯一执行权，并受公平性与控制服务预算约束。

进一步优先级来自通用加权路径、后继释放和访问局部性提示，未知时回到普通队列；不按算子名称、case 或 seed 硬编码。长链总工作量不等于当前可分配工作，扇出大不等于立即解锁多任务；不为精确打分重复扫描全图。软亲和让位于闲核领取，不能永久固定一条链给一个核心。每个细调用完成后及时推进通知，避免批末才发布造成额外关键路径等待。

## 正确性与资源

同一任务最多有一个有效租约；取出与窃取竞争必须线性化。队列满时返回拒收，依赖模块保留 ReadyPending。队列空只代表当前无可取任务，不代表执行完成。

等待策略由驱动协调：短暂自旋后可停放线程，但停放前重新检查进度代次或唤醒序号以避免丢失唤醒。任务或控制事件进入均可触发必要唤醒。禁止将“所有就绪队列空”用作终止条件。
