# 面向评测工作负载的运行时设计

> **非规范文档**：项目唯一需求与验收依据见 [REQUIREMENTS.md](../REQUIREMENTS.md)。本页仅说明实现、使用方式、设计候选或历史验证；其中的约束性表述不能新增、覆盖或缩小规范要求。

> **当前实现（2026-10-30）**：严格 Python 前端生成参数化程序/访问 Metadata；并行执行在绑定时构造通用区域 CSR，使用连续计数、atomic/owner 后端和加锁本地队列/逐任务窃取。默认 `DAG_MODE=auto`、`DAG_BACKEND=atomic`、`DAG_BATCH=1`；线程数默认取实际单 NUMA 允许集。`auto` 在首次计算前按任务数不超过 `2*planned_workers` 选择原顺序小任务执行；显式 `serial` 流式执行。当前实现见 [实现说明](implementation.md)。

本文余下保留原设计决策与候选优化；隐式关系、rank/unrank、链压缩、窗口、自适应批量及复杂优先级尚未实现。

## 目标与决策

首要目标是在给定 case 上降低完整计算时间。通用性是正确性和合规要求，其他算法及未见参数的性能作为次要回归指标；不为追求所有 DAG 上的最优复杂度拖慢主路径。允许针对目标机器和公开工作负载调优，但策略只能使用源码/Metadata 推导的结构、实际形状、资源和成本特征，不能识别 case 编号、seed、输入文件名、预存答案或公开参数白名单。n、b 保持评委设置，官方调用语义和次数不因调优改变。

原设计按 13 个逻辑模块划分，曾规划的第一条并行路径采用：参数化 Metadata、紧凑显式任务状态、隐式后继关系、直接原子递减、本地就绪队列和有界小批窃取。状态能够放入预算时先实现这条路径，但不声称它已实测最快。所有者消息后端、关系缓存、就绪批处理均通过总时间对照决定是否启用；链压缩和窗口不是第一阶段的前置工作。

## 评分约束与图质量

按已记录规则，运行性能最高 85 分、Metadata 编码最高 15 分，均按排名；不新增图质量分数或时间/字节线性加权。以 [需求规范](../REQUIREMENTS.md) 的 T_score 和实际必要产物字节作最终对照，图的冲突覆盖、额外先后约束、关键路径与通知数量用于解释性能。离线分析可以多花时间，加载 Metadata、实例建图、计数准备与执行都计时。

主路径采用精确访问推导和去重关系，减少不必要的等待，不把源码循环结束当成所有任务的全局屏障。例如 demo 的一个 madd 只等待实际输入块准备好和目标块先前访问结束，无需等待整轮无关 trsm；下一轮 cholesky 也不等待无关尾部更新。对角 madd 两个输入相同，应去重前驱，不能变成两条相同通知。所有这些规则从源码/访问契约推导，不手写 Cholesky DAG。

保留依赖可达性的传递边约简降低通知成本，但不改变理想并行度；减少保守多加的依赖才可能释放更多并行。批量执行保持原调用与逐调用完成语义，不能为了 Metadata 更短而隐式添加整批屏障。新增算子通过目录和 ABI 适配扩展，正式分块路径仍调用官方 cholesky/trsm/madd。

## 规模依据

公开 20 条规格最大 q=n/b=48。现已取得 demo 实际源码：q 次 cholesky、q(q-1)/2 次 trsm、q(q-1)(q+1)/6 次 madd，合计 V_call=q(q+1)(q+2)/6。q=48 时 V_call=19,600；每调用状态假设 32–64 字节约 0.60–1.20 MiB，尚未包含复制/清零任务、队列和缓存。

这是 demo 源码的调用计数审计依据，不是 runtime 中的算法特判。含准备/收尾任务的实际 V、去重 E、最大前驱数与成本仍由源码及 Metadata 推导。既不因立方复杂度预设公开集内存不足，也不把 q=48 当成隐藏规模上限。朴素算法若有 Θ(n³) 次调用，调用次数不会被小 Metadata 或状态压缩消除。

## 各种表示独立选择

| 维度 | 原设计起点 | 有证据再选择的替代 |
| --- | --- | --- |
| 依赖关系 | 参数化后继枚举、前驱基数程序 | 在预算内物化部分关系或完整 CSR，减少重复解释 |
| 任务状态 | [0,V) 的连续数组；启动前完成计数初始化 | 稀疏按需状态；经证明的链进度 |
| 计数同步 | 完成者直接原子递减目标计数 | 单写所有者＋聚合消息 |
| 调度单位 | 细任务 ID，可批量领取已经就绪的任务 | 经证明全部就绪的可拆分范围、有限直接续执行 |
| 选择顺序 | 本地获取、有限窃取、避免饥饿 | 低成本关键路径/释放后继提示、软数据亲和 |
| 内存控制 | 执行前选择表示并预留预算 | 每次执行中动态调整展开、缓存与批量；安全边界切换 |

磁盘 Metadata 不包含针对某个评测参数预展开的图；运行时依照实际参数构建状态或边缓存是允许的设计选择，其初始化、分配、触页、建图和内存必须完整计量。若固定公开参数表才能触发快速路径，则不属于该设计。

## 原设计执行协议与扩展要求

1. 在计时范围内加载 Metadata、准备资源，绑定合法参数和 ABI，求 V 与容量界，选择 ExecutionPlan。规则任务域用编译器生成的 rank/unrank 映射到 DenseTaskId，不假设 ID 顺序就是拓扑顺序。
2. DependencyTracker 分配连续存储，为全部任务设置去重前驱计数，并预留唯一待发布记录所需空间。所有计数和只读表初始化完毕、经启动同步发布后，才允许源任务和内核运行，避免“通知先到、随后初始化覆盖”的竞态。
3. 源码中的 A→L 复制须先完成（或表示为有等价依赖的任务），不能作为文件 I/O 隐藏；源任务经唯一入口发布。worker 获取一个或一小批就绪任务，按原 ABI 调用官方内核。
4. 每次内核返回后，以预算限制后继枚举；对每个后继恰好一次递减。最后一次递减取得唯一发布权。队列拒收时保存 ReadyPending，不重减计数；继续处理控制工作和可执行工作。
5. 完成一次调用即可推进其后继，不等批内所有调用结束。不能为了少一次队列操作而把跨批依赖推迟成整批屏障。
6. 所有源枚举结束、全部 V 个任务完成传播并排空，完成源码要求的上三角清零及结果整理后返回。复制/清零若已表达为任务则不重复执行，若作为明确前后阶段则同样保留语义和计时。连续数组保留到排空再整体释放/重置，基础路径无需每任务远程 retire 消息或并发对象回收。

原子后端最初使用 acquire-release 的递减，最后完成者汇聚前驱写后通过 release 入队，执行者 acquire 取任务。初始化、计数、队列和失败状态分别定义内存序，不以 AArch64 上偶然通过代替证明。细节见 [依赖状态](modules/dependency_tracker.md)。

## 负载均衡与访存

工作量按预计耗时分配，不按链数、节点数静态均分。初始使用保守小批，成本模型缺失时维持简单策略；可按算子 ABI/参数形状抽样计时，聚合为估计，不为每个节点存耗时。worker 的私有已领取工作有数量和预计时间上限。就绪工作少、其他 worker 空闲或进入尾部时缩小批量，保留可窃取工作；工作充足且调用很短时才增加批量。同步内核内部不能抢占，控制工作延迟至少受单次最长调用限制。

成本估计只影响选择，不影响依赖。严格链同一时刻只能执行其满足外部依赖的下一步，不能为了均衡把串行链并行运行。独立范围可以切分；链间连接保留细节点的进度门槛，不用“等待整链结束”替代。只有可执行工作足够，才可能持续利用全部核心。

优先级作为后续候选：从通用依赖结构估计到终点的加权距离或推进后继的作用，不按算子名字写死优先级。大量出边不代表立即释放大量任务；不为精确计算优先级每轮扫描全 DAG。完整反向关键路径计算仅在已物化图且总成本有收益时使用，其余采用廉价提示或普通队列。定期服务旧任务，软亲和不能让空闲核心等待专属任务。

runtime 热路径优先直接 ID 索引、参数常量折叠、去重后稀疏关系、预分配连续存储和局部临时缓冲。计数与冷参数分离，但 SoA 与紧凑 AoS 均需测量；不为每个任务填充缓存行，只隔离 worker 高频元数据等已知竞争位置。缓存行、cache/NUMA 层级从目标机获取。预取、大页、消息聚合、批量关系求值依次实验，不同时堆叠后归因。

用户指定测试机器为 Kunpeng-920、2 Socket × 64 核、125 GB 内存，操作系统约束仍为 Ubuntu 22.04。单 NUMA 实际允许集内的全部核心可参与；socket 不等于 NUMA 节点，24 不作为上限，125 GB 不直接作为本进程本地预算。线程 affinity、首次触页、内存放置和内核内部线程共同决定配置。优先优化总时间，CPU 自旋比例不算有效利用率。

## 内存预算与继续执行的条件

矩阵/工作区、Metadata 与绑定常量、状态、就绪记录、控制队列、枚举游标、线程栈、可选缓存分别计量。显式路径估算为 O(M+V+Q+P*B)，若物化边再加 O(V+E)；B 为每线程受限临时额度。使用实际字段宽度、填充和分配器开销计算字节，32–64 字节仅是上面的示例。进程限制、配置预算与节点可用量共同约束预算，扣除已计量的非调度内存及预留余量；整机空闲内存仅为辅助观测。

连续模式不依赖单任务回收来维持进度：计数和每任务唯一待发布记录提前留足，通知流式生成，队列满则停止继续生成并消费现有工作，不能停掉全部就绪执行。队列、完成游标与通知的保留空间在启动前核算，任何拒收都有唯一持有者和续传位置。动态降低软展开额度不撤销已发放额度、不丢弃状态，无法满足新的硬限制时安全失败。

显式布局不可行时，首先尝试已证明等价且准备成本可接受的其他布局。按需状态只降低常见占用，F 仍可能达到 V，不能承诺严格前沿上界。保留一种可验证的低内存通用途径：编译器提供涵盖全部任务的原程序顺序游标时，串行逐个执行，前序调用返回后再推进，不创建依赖计数；它必须保留所有语义任务并有有界游标空间，不能回避初始化或副作用。该路径在执行开始前选择，泛化性能可较低；能力缺失或基本缓冲区仍放不下则明确失败。

链压缩、拓扑固定窗口与滑动窗口均为延后候选。启用链压缩须证明任务覆盖、外部进度门槛、唤醒机制和进度寿命，不通过反复全链扫描找就绪。窗口须支持窗口内前驱计数，且既往已完成前缀确实覆盖跨窗口依赖；不能在任意中途清空状态切窗口。任何模式切换仅发生于新的矩阵执行或经证明且已排空的安全边界。
