# 运行流程与调度

本文描述当前代码。使用命令见 [README](../README.md)，要求及待确认事项见 [REQUIREMENTS](../REQUIREMENTS.md)。

## 从源码到结果

算法驱动由 `compiler/compile.py` 解析。算子的读写范围由 `compiler/infer_catalog.py` 借助 Clang 从实现源码推导；显式 catalog 仍是兼容入口。循环、条件、调用参数及访问表达式写入 Metadata。

运行时用实际 n、b 绑定这些表达式，产生任务，再选择串行、依赖图或分窗口执行。具体算子由 `src/main.cpp` 调用，结果写入 L。

| 文件 | 主要职责 |
| --- | --- |
| [core.hpp](../include/dag/core.hpp) | Program、Task、Region、Graph 和执行器接口 |
| [metadata.cpp](../src/metadata.cpp) | 解码、槽位绑定、求值、循环压缩和窗口生成 |
| [graph.cpp](../src/graph.cpp) | 从访问区域推导读写依赖 |
| [runtime.cpp](../src/runtime.cpp) | 线程池、就绪队列、完成通知和独立任务执行 |
| [main.cpp](../src/main.cpp) | 输入输出、预算、执行路径及公共算子绑定 |

`Program` 是参数化程序；`Task` 是具体调用或一段压缩调用；`Graph` 保存任务之间的顺序约束。Metadata、内存图和输出矩阵是不同的产物。

## 依赖图路径

`instantiate` 按源码控制流程生成任务，`build_graph` 根据读写区域连边。读者等待此前写者，写者等待此前读者和写者，共享只读区域不产生依赖。

规则访问先尝试网格表示：将实际矩形区域映射到块 ID。几何条件不满足时，使用通用区间分析。图按邻接数组保存后继，另存初始入度。

默认 atomic 后端在任务完成时递减后继等待计数，减到零的任务变为就绪。线程使用本地队列和工作窃取，并可直接继续执行一个刚就绪的后继。owner 后端通过所属线程处理通知，可显式选择。

首部全矩阵复制和尾部上三角清零可以提到数值图前后执行，但不会省略，也仍计时。小工作量可能直接串行执行，避免线程调度成本。

## 循环压缩

对循环体为单个调用、参数和区域按迭代仿射变化、访问几何符合要求且迭代间没有读写冲突的循环，可以用较少的任务表示连续调用。

压缩任务保存第一项参数、`repeat` 和参数/访问偏移增量。执行时仍逐次调用公共算子，保持实际调用次数和必要顺序。无法证明可压缩时继续普通展开。

- `DAG_LOOP_CHUNK`：每段最多包含多少次迭代。
- `DAG_LOOP_PARTS`：将迭代范围均分为多少段，正值优先于 chunk。
- 显式 `chunk=1, parts=0` 保留逐调用表示。
- 自动压缩在图路径使用约 `ceil(workers/2)` 段，在 pattern 路径使用 worker 数，在串行流式路径使用一段。它是粒度策略，不是线程上限。

scalar 应用和显式步数限制保留相应的原解释路径。段过大可能损失并行度，段过小又会增加准备和调度成本；选型依据完整耗时。

## 分窗口路径

`enumerate_pattern` 从已有循环和读写表达式证明独立循环或独立嵌套循环，生成有界窗口。窗口内独立任务通过 `Executor::run_independent` 并行执行，全部完成后才进入下一窗口；无法证明并行的区域按源码顺序推进。

这条路径不为独立窗口建立完整 CSR 和逐任务入度，减少全图存储与通知。代价是窗口间的等待：它可能失去细粒度图允许的跨阶段重叠，目前不做跨阶段 lookahead。

`DAG_SCHEDULE=graph|pattern|auto` 选择路径。当前 auto 对分块应用的 `n/b >= 64` 考虑 pattern，小规模保留图路径；显式步数限制等条件仍影响选择。这个阈值不保证对所有机器和算法最优。

报告的 `tasks` 是逻辑调用次数，`peak_window_tasks` 是最大活动窗口的任务数。pattern 的 `graph_bytes` 表示活动任务容器估算，不是完整图规模或进程 RSS。

## 资源与生命周期

case 按顺序执行，Metadata、线程池和矩阵容量可复用。新增矩阵区域在输入读取或算子执行前初始化；已有线程池可承担并行初始化。初始化、触页、回收和最终释放都计入运行时计算时间。

预算来自实际允许的单 NUMA 资源和进程限制。矩阵按实际容量计费，图预算扣除 Metadata、矩阵、线程池及算子工作空间。多余矩阵容量在压力下可回收。

图路径在开始数值工作前遇到资源不足，可清理准备状态并选择串行流式执行。任何数值写入开始后，失败都不能通过重跑算法来恢复。pattern 边生成边执行，也必须遵守这条边界。

## 观察性能

先看完整耗时，再用准备时间、执行时间、图大小和窗口数解释原因。关键路径、缓存争用、算子成本、调度成本分别限制性能，任务更少或边更少不自动代表更快。

运行时只排除矩阵文件 I/O，校验由独立程序完成。源码分析和生成 Metadata 的比赛计时归属见需求 O-08；调度估算工具的结果也不能代替端到端测量。
